# Accessible motion and responsive patterns — Examples

This exercise builds a small Sass page with a fluid card grid, a viewport breakpoint for the page layout, a container query for each reusable card, and an optional entrance animation that respects reduced-motion preferences.

## 1. Create the sample project

~~~text
accessible-responsive-demo/
  index.html
  src/
    _breakpoints.scss
    _motion.scss
    app.scss
    components/
      _product-card.scss
  dist/
    app.css             generated by Dart Sass
~~~

The <code>dist/app.css</code> file is generated output. Edit the Sass source, then compile again.

## 2. Add a breakpoint module

Create <code>src/_breakpoints.scss</code>:

~~~scss
@use "sass:map";

$breakpoints: (
  content-wide: 48rem
);

@mixin above($name) {
  $min-width: map.get($breakpoints, $name);

  @if $min-width == null {
    @error "Unknown breakpoint: #{$name}";
  }

  @media (min-width: $min-width) {
    @content;
  }
}
~~~

This project has one named viewport breakpoint. It is named for the content change it enables, rather than a device category.

## 3. Create the product card component

Create <code>src/components/_product-card.scss</code>:

~~~scss
.product-card {
  min-inline-size: 0;
  padding: 1rem;
  border: 1px solid #cbd5e1;
  border-radius: 0.75rem;
  background: #fff;
  color: #172033;

  // The inner layout can respond to the card's own allocated width.
  container-type: inline-size;
}

.product-card__layout {
  display: grid;
  grid-template-columns: minmax(0, 1fr);
  gap: 1rem;
}

.product-card__art {
  display: grid;
  min-block-size: 9rem;
  place-items: center;
  border-radius: 0.5rem;
  background: linear-gradient(135deg, #5b21b6, #c084fc);
  color: #fff;
  font-size: 1.5rem;
  font-weight: 700;
}

.product-card__content {
  min-inline-size: 0;
}

.product-card__title {
  margin-block: 0 0.5rem;
  font-size: 1.2rem;
}

.product-card__description {
  margin-block: 0;
  color: #475569;
}

.product-card__price {
  margin-block: 1rem 0;
  font-weight: 700;
}

.product-card__link {
  display: inline-block;
  margin-block-start: 1rem;
  color: #5b21b6;
  text-underline-offset: 0.2em;
}

.product-card__link:focus-visible {
  outline: 3px solid #7c3aed;
  outline-offset: 3px;
}

@container (min-width: 34rem) {
  .product-card__layout {
    grid-template-columns: minmax(0, 1fr) 12rem;
    align-items: start;
  }

  .product-card__art {
    grid-column: 2;
    grid-row: 1;
  }

  .product-card__content {
    grid-column: 1;
    grid-row: 1;
  }
}
~~~

The base card is a single column. When its own container is wide enough, the decorative art and text sit beside each other. If container queries are unavailable, the base layout is still complete.

## 4. Add a reduced-motion-aware notice

Create <code>src/_motion.scss</code>:

~~~scss
.notice {
  margin-block: 1.5rem;
  padding: 1rem;
  border-inline-start: 0.35rem solid #5b21b6;
  border-radius: 0.25rem;
  background: #f3e8ff;
  color: #2e1065;
  opacity: 1;
  transform: none;
}

// The static state above is complete. Add the decorative entrance only
// when the user has not requested reduced motion.
@media (prefers-reduced-motion: no-preference) {
  .notice[data-entering="true"] {
    animation: notice-enter 180ms ease-out both;
  }
}

@keyframes notice-enter {
  from {
    opacity: 0;
    transform: translateY(0.5rem);
  }

  to {
    opacity: 1;
    transform: translateY(0);
  }
}
~~~

The notice is visible and readable by default. Its message does not depend on the animation. When the user requests reduced motion, the optional animation rule does not match.

## 5. Create the Sass entry point

Create <code>src/app.scss</code>:

~~~scss
@use "breakpoints" as bp;
@use "components/product-card";
@use "motion";

:root {
  color-scheme: light;
  font-family: system-ui, sans-serif;
  line-height: 1.5;
  color: #172033;
  background: #f8fafc;
}

* {
  box-sizing: border-box;
}

body {
  margin: 0;
}

.site-header,
.page-content {
  width: min(100% - 2rem, 72rem);
  margin-inline: auto;
}

.site-header {
  padding-block: 1.5rem;
}

.site-title {
  margin: 0;
  font-size: clamp(1.6rem, 1.2rem + 2vw, 2.5rem);
}

.page-intro {
  max-width: 65ch;
  color: #475569;
}

.catalog-layout {
  display: grid;
  grid-template-columns: minmax(0, 1fr);
  gap: 2rem;
  padding-block-end: 3rem;
}

.catalog-grid {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(min(100%, 18rem), 1fr));
  align-content: start;
  gap: 1rem;
}

.catalog-notes {
  padding: 1rem;
  border: 1px solid #cbd5e1;
  border-radius: 0.75rem;
  background: #fff;
}

.catalog-notes h2 {
  margin-block-start: 0;
}

.catalog-details {
  display: grid;
  gap: 1rem;
  padding-block-end: 3rem;
}

.catalog-detail {
  padding: 1rem;
  border: 1px solid #cbd5e1;
  border-radius: 0.75rem;
  background: #fff;
  scroll-margin-block: 1rem;
}

.catalog-detail h3 {
  margin-block-start: 0;
}

@include bp.above(content-wide) {
  .catalog-layout {
    grid-template-columns: minmax(0, 2fr) minmax(14rem, 1fr);
    align-items: start;
  }
}
~~~

The <code>auto-fit</code> grid adapts the number of card columns to the available space, so it does not need a separate media query for each column count. The named breakpoint is used only for the page-level content and notes layout.

Create <code>index.html</code> in the project root:

          <p>
            Resize the page to see the catalog grid reflow. The page notes move
            beside the catalog at the content-wide breakpoint.

~~~

The page uses headings and article elements for content structure. The decorative artwork is marked <code>aria-hidden</code> because it contributes no information. The notice has a status role and readable text, so the animation is not the only feedback.

The sample links jump to the matching component details section below the catalog.

## 7. Compile the Sass

From the project root, create the output folder and compile:

~~~sh
mkdir dist
sass --style=expanded src/app.scss dist/app.css
~~~

For continuous local development, use the Sass watch mode:

~~~sh
sass --watch src/app.scss:dist/app.css
~~~

Open <code>index.html</code> in a browser through a local static server. If the Sass CLI is not available, install Dart Sass using the method documented by the Sass project before compiling.

## 8. Review the responsive and motion states

Use the browser and operating system settings to inspect the example:

1. Resize the viewport gradually. The card grid should add or remove columns without a device-specific rule for every width.
2. Make the page wide, then constrain an individual card in developer tools. Its internal layout should respond to its card container, not merely to the page viewport.
3. Enable the system's reduced-motion setting or emulate <code>prefers-reduced-motion: reduce</code> in developer tools. The status notice should remain visible and the entrance motion should not run.
4. Disable the reduced-motion setting. The notice may use its short entrance effect, while its message stays readable.
5. Tab through the links. Confirm that each focus state is visible.
6. Test a narrow viewport and browser zoom. Check for clipped text, horizontal scrolling, and controls or content that cannot be reached.

## 9. Try these extensions

- Add a second named breakpoint only when the page content needs another structural change.
- Put a card in a narrow sidebar while keeping the viewport wide, then confirm its container query still chooses the stacked layout.
- Add a decorative parallax effect behind the catalog, then remove it for reduced motion. Keep all meaningful content in normal document flow.
- Add a carousel with explicit controls and investigate how automatic movement should be paused or stopped.
- Inspect the compiled CSS to see the media query and container query that Dart Sass emitted.

## Expected behavior

- At narrow widths, the page and cards remain in a readable single-column flow.
- The card grid fits columns based on available space.
- A page-level breakpoint can place catalog notes next to the main content.
- A card's inner layout changes based on its own container width.
- The reduced-motion path keeps the status message visible and removes the optional entrance movement.
- Keyboard focus remains visible on card links.
