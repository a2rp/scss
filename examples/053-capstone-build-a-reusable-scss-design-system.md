# Capstone: build a reusable SCSS design system - Examples

This exercise builds a small, reusable design system rather than a collection of disconnected snippets. It includes a public Sass API, private token maps, runtime theme variables, two components, one compiled CSS entry point, and a consumer guide.

## 1. Create the project structure

~~~text
scss-design-system-demo/
  index.html
  styles/
    _index.scss
    app.scss
    foundation/
      _base.scss
      _theme.scss
      _tokens.scss
    components/
      _button.scss
      _card.scss
  dist/
    app.css                         generated by Dart Sass
~~~

The <code>styles/_index.scss</code> file is the Sass API. The <code>styles/app.scss</code> file is the CSS entry point. The token module contains no component CSS, so consumers can load its API without emitting the whole system.

## 2. Create the token module

Create <code>styles/foundation/_tokens.scss</code>:

~~~scss
@use "sass:map";

$-space-scale: (
  1: 0.25rem,
  2: 0.5rem,
  3: 0.75rem,
  4: 1rem,
  6: 1.5rem,
  8: 2rem
);

$-radius-scale: (
  small: 0.25rem,
  medium: 0.5rem,
  large: 0.875rem
);

$-breakpoints: (
  content-wide: 48rem
);

@function space($step) {
  $value: map.get($-space-scale, $step);

  @if $value == null {
    @error "Unknown spacing step: #{$step}";
  }

  @return $value;
}

@function radius($size) {
  $value: map.get($-radius-scale, $size);

  @if $value == null {
    @error "Unknown radius: #{$size}";
  }

  @return $value;
}

@mixin above($name) {
  $min-width: map.get($-breakpoints, $name);

  @if $min-width == null {
    @error "Unknown breakpoint: #{$name}";
  }

  @media (min-width: $min-width) {
    @content;
  }
}
~~~

The leading dash marks implementation maps as private to this Sass module. Consumers use the checked functions and mixin instead of relying on the map structure.

## 3. Expose a narrow public API

Create <code>styles/_index.scss</code>:

~~~scss
@forward "foundation/tokens" show space, radius, above;
~~~

A consumer stylesheet in the project root can now use the public members:

~~~scss
@use "styles" as ds;

.demo {
  padding: ds.space(4);
  border-radius: ds.radius(medium);
}

@include ds.above(content-wide) {
  .demo {
    padding: ds.space(6);
  }
}
~~~

The API keeps a namespace and exposes only the members consumers should rely on. The forwarded token module has no CSS rules, so loading the API does not emit component styles.

## 4. Define runtime theme tokens

Create <code>styles/foundation/_theme.scss</code>:

~~~scss
:root,
[data-theme="light"] {
  color-scheme: light;
  --color-page: #f8fafc;
  --color-surface: #fff;
  --color-text: #172033;
  --color-muted: #475569;
  --color-border: #cbd5e1;
  --color-action: #4f46e5;
  --color-action-hover: #3730a3;
  --color-on-action: #fff;
  --color-focus: #7c3aed;
}

[data-theme="dark"] {
  color-scheme: dark;
  --color-page: #0f172a;
  --color-surface: #1e293b;
  --color-text: #f8fafc;
  --color-muted: #cbd5e1;
  --color-border: #475569;
  --color-action: #a78bfa;
  --color-action-hover: #c4b5fd;
  --color-on-action: #1e1b4b;
  --color-focus: #c4b5fd;
}
~~~

These are browser-resolved values. Components can use the same role names in either theme, and a nested element can set <code>data-theme</code> to override its subtree.

## 5. Add base styles

Create <code>styles/foundation/_base.scss</code>:

~~~scss
:root {
  font-family: system-ui, sans-serif;
  line-height: 1.5;
}

*,
*::before,
*::after {
  box-sizing: border-box;
}

body {
  min-block-size: 100vh;
  margin: 0;
  background-color: #f8fafc;
  background-color: var(--color-page, #f8fafc);
  color: #172033;
  color: var(--color-text, #172033);
}

h1,
h2,
h3 {
  line-height: 1.2;
}

.page-shell {
  width: calc(100% - 2rem);
  max-inline-size: 72rem;
  margin-inline: auto;
}

.site-header {
  padding-block: 2rem;
}

.site-title {
  margin: 0;
  font-size: 1.75rem;
  font-size: clamp(1.75rem, 1.3rem + 2vw, 2.75rem);
}

.site-intro {
  max-inline-size: 65ch;
  color: #475569;
  color: var(--color-muted, #475569);
}

.section-heading {
  margin-block: 0 1rem;
}

.site-footer {
  margin-block-start: 3rem;
  padding-block: 1.5rem;
  border-block-start: 1px solid #cbd5e1;
  border-block-start-color: var(--color-border, #cbd5e1);
  color: #475569;
  color: var(--color-muted, #475569);
}
~~~

The earlier declarations provide simple values before the custom-property declarations. The <code>clamp()</code> value is an optional enhancement to the fixed font size.

## 6. Create a reusable button component

Create <code>styles/components/_button.scss</code>:

~~~scss
@use "../index" as ds;

.button {
  display: inline-flex;
  min-block-size: 2.75rem;
  align-items: center;
  justify-content: center;
  gap: ds.space(2);
  padding: ds.space(2) ds.space(4);
  border: 1px solid transparent;
  border-radius: ds.radius(medium);
  background-color: #4f46e5;
  background-color: var(--color-action, #4f46e5);
  color: #fff;
  color: var(--color-on-action, #fff);
  font: inherit;
  font-weight: 650;
  text-align: center;
  text-decoration: none;
  cursor: pointer;
}

.button:hover {
  background-color: #3730a3;
  background-color: var(--color-action-hover, #3730a3);
}

.button:focus {
  outline: 3px solid #7c3aed;
  outline-color: var(--color-focus, #7c3aed);
  outline-offset: 3px;
}

@supports selector(:focus-visible) {
  .button:focus:not(:focus-visible) {
    outline: none;
  }

  .button:focus-visible {
    outline: 3px solid #7c3aed;
    outline-color: var(--color-focus, #7c3aed);
    outline-offset: 3px;
  }
}

.button:disabled {
  cursor: not-allowed;
  opacity: 0.65;
}
~~~

The component works for an anchor or a button element when used according to its semantics. It defines a visible focus fallback and a more specific focus-visible treatment where supported.

## 7. Create a reusable card component

Create <code>styles/components/_card.scss</code>:

~~~scss
@use "../index" as ds;

.card {
  min-inline-size: 0;
  padding: ds.space(4);
  border: 1px solid #cbd5e1;
  border-color: var(--color-border, #cbd5e1);
  border-radius: ds.radius(large);
  background-color: #fff;
  background-color: var(--color-surface, #fff);
  color: #172033;
  color: var(--color-text, #172033);
  box-shadow: 0 0.25rem 1rem rgb(15 23 42 / 0.08);
}

.card__eyebrow {
  margin-block: 0 0.5rem;
  color: #475569;
  color: var(--color-muted, #475569);
  font-size: 0.875rem;
  font-weight: 650;
  letter-spacing: 0.04em;
  text-transform: uppercase;
}

.card__title {
  margin-block: 0 0.75rem;
  font-size: 1.25rem;
}

.card__body {
  margin-block: 0;
  color: #475569;
  color: var(--color-muted, #475569);
}

.card__actions {
  display: flex;
  flex-wrap: wrap;
  gap: ds.space(3);
  margin-block-start: ds.space(4);
}
~~~

Spacing and radius come from Sass functions. Surface, text, and border colors come from runtime theme properties. This keeps component structure independent from a particular theme palette.

## 8. Compose the application stylesheet

Create <code>styles/app.scss</code>:

~~~scss
@use "index" as ds;
@use "foundation/theme";
@use "foundation/base";
@use "components/button";
@use "components/card";

.demo-grid {
  display: grid;
  grid-template-columns: minmax(0, 1fr);
  gap: ds.space(4);
}

@include ds.above(content-wide) {
  .demo-grid {
    grid-template-columns: repeat(2, minmax(0, 1fr));
  }
}

.theme-preview {
  margin-block-start: ds.space(8);
  padding: ds.space(4);
  border: 1px solid #cbd5e1;
  border-color: var(--color-border, #cbd5e1);
  border-radius: ds.radius(large);
  background-color: #fff;
  background-color: var(--color-surface, #fff);
  color: #172033;
  color: var(--color-text, #172033);
}
~~~

This is the system's CSS output entry point. The API module contributes Sass members, while the other modules contribute the system's theme, base styles, and components.

## 9. Build a consuming page

Create <code>index.html</code> in the project root:

~~~html

<html lang="en" data-theme="light">
  <head>
    <meta charset="utf-8">

    </header>

    <main class="page-shell">
      <section id="components" aria-labelledby="components-heading">
        <h2 class="section-heading" id="components-heading">
          System components
        </h2>

        <div class="demo-grid">
          <article class="card" id="button-card">
            <p class="card__eyebrow">Component 01</p>
            <h3 class="card__title">Action button</h3>
            <p class="card__body">
              Buttons and button-like links use the action color role, shared
              spacing, rounded corners, and a visible keyboard focus state.
            </p>
            <div class="card__actions">
              <button class="button" type="button" disabled>Unavailable action</button>
              <a class="button" href="#theme-preview">View theme</a>
            </div>
          </article>

          <article class="card" id="content-card">
            <p class="card__eyebrow">Component 02</p>
            <h3 class="card__title">Content card</h3>
~~~

The HTML uses native buttons for actions and anchors for navigation. The nested dark-theme preview is a static example of inherited custom properties; a production theme switch would need its own user interface and behavior.

## 10. Compile the system

From the project root, create the output directory and compile the one entry point:

~~~powershell
New-Item -ItemType Directory -Force dist
sass --style=expanded styles/app.scss dist/app.css
~~~

Open <code>index.html</code> through a local static server. If the Sass CLI is not available, install Dart Sass using the official Sass installation guide.

A consuming stylesheet can load only the Sass API:

~~~scss
@use "styles" as ds;

.custom-panel {
  padding: ds.space(4);
  border-radius: ds.radius(medium);
}
~~~

Compile this consumer stylesheet from a file located at the project root, or adjust the module path relative to the consumer file. Loading the API does not include the component CSS because the forwarded token module contains no style rules.

## 11. Review the system

Review the generated CSS and the page in a browser:

1. Confirm the application entry point includes base, theme, button, and card styles once.
2. Resize the page. The component grid should move from one column to two at the named breakpoint.
3. Check the light page and dark nested region. Text, borders, action states, and focus indicators should remain legible.
4. Tab through every link and button. Confirm each keyboard focus indicator is visible.
5. Try a narrow viewport, browser zoom, and enlarged text. Look for clipped text and horizontal overflow.
6. Inspect <code>dist/app.css</code>. Confirm Sass functions resolved to CSS values, while theme variables and their selectors remain in the output.
7. Load the public Sass API from a separate consumer file. Confirm it exposes the intended functions without emitting component styles.
8. Review the README instructions as if you were a new consumer: entry point, API, theming, and customization should be clear.

## 12. Suggested README outline for the capstone

The system's own README can document:

~~~markdown
# SCSS Design System

## Overview
What the system provides and which products should use it.

## Installation
How to install dependencies and include the compiled stylesheet.

## Compile
The Dart Sass command and the single source entry point.

## Public Sass API
How to load the API and which functions and mixins are supported.

## Themes
Which data attribute selects a theme and which CSS custom properties are public.

## Components
Available classes, semantic HTML expectations, and accessible states.

## Browser support
The consuming project's target policy and fallback behavior.

## Contributing
How to add a token or component and review generated output.

## Versioning
How public API changes are communicated.
~~~

Treat these sections as a starting contract. Adapt them to the project's actual package and release process rather than documenting features that are not implemented.

## Expected result

- Sass token maps remain private and checked functions provide the public token API.
- One stylesheet entry point generates the system CSS.
- Light and dark themes use runtime custom properties.
- Buttons and cards share spacing, radius, and color roles.
- Fallback declarations precede custom-property declarations.
- The nested dark preview uses the same component styles without duplicating a second component implementation.
- The README outline explains how a consumer can adopt and maintain the system.
