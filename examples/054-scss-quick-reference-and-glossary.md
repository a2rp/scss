# SCSS quick reference and glossary - Examples

This worked example brings the final chapter's ideas together in one small project. It has a configurable Sass module, a public module entry point, runtime CSS theme variables, a reusable component, and repeatable build commands.

For the concepts behind the code, see the [quick reference lesson](../lessons/054-scss-quick-reference-and-glossary.md) and its [Q&A](../qnas/054-scss-quick-reference-and-glossary.md).

## 1. Project structure

Create this structure:

~~~text
scss-quick-reference-demo/
  package.json
  index.html
  src/
    scss/
      main.scss
      _theme.scss
      foundation/
        _index.scss
        _tokens.scss
      components/
        _button.scss
  dist/
    main.css                 generated by Dart Sass
    main.css.map             generated source map
~~~

Files whose names begin with an underscore are Sass partials. They are loaded by another Sass file and are not compiled as independent output entry points.

## 2. Add build scripts

Create <code>package.json</code>:

~~~json
{
  "private": true,
  "scripts": {
    "css:build": "sass --style=expanded src/scss/main.scss dist/main.css",
    "css:watch": "sass --watch --style=expanded src/scss:dist"
  },
  "devDependencies": {
    "sass": "^1.108.2"
  }
}
~~~

The dependency range above is illustrative. For a real project, install the current approved Sass version with the package manager and commit the resulting lockfile so the exact dependency graph is reproducible.

Install the dependencies and compile:

~~~sh
npm install
npm run css:build
~~~

For development, use:

~~~sh
npm run css:watch
~~~

The first path in the build command is the Sass entry point. The second is the generated CSS destination.

## 3. Build a configurable token module

Create <code>src/scss/foundation/_tokens.scss</code>:

~~~scss
@use "sass:map";

$brand: #2457c5 !default;

$-spaces: (
  1: 0.25rem,
  2: 0.5rem,
  3: 0.75rem,
  4: 1rem,
  6: 1.5rem
);

$-breakpoints: (
  wide: 48rem,
  extra-wide: 72rem
);

@function space($step) {
  $value: map.get($-spaces, $step);

  @if $value == null {
    @error "Unknown spacing step: #{$step}.";
  }

  @return $value;
}

@mixin focus-ring($color: $brand) {
  &:focus-visible {
    outline: 3px solid $color;
    outline-offset: 2px;
  }
}

@mixin from($name) {
  $width: map.get($-breakpoints, $name);

  @if $width == null {
    @error "Unknown breakpoint: #{$name}.";
  }

  @media (min-width: $width) {
    @content;
  }
}
~~~

The public <code>$brand</code> variable has a default so the module can be configured. The maps begin with <code>$-</code> to mark them private. Consumers use the checked function and mixins instead of depending directly on internal map structure.

The <code>from()</code> mixin checks the requested breakpoint and places caller-provided styles in a media query. The error makes a misspelled breakpoint fail with a useful message.

## 4. Expose a small module API

Create <code>src/scss/foundation/_index.scss</code>:

~~~scss
@forward "tokens";
~~~

This file is the public entry point for the foundation module. Consumers can load <code>foundation</code> and use its public members without referring to the internal <code>tokens</code> filename.

## 5. Add runtime theme variables

Create <code>src/scss/_theme.scss</code>:

~~~scss
@use "foundation" as foundation;

:root {
  color-scheme: light;
  --color-brand: #{foundation.$brand};
  --color-page: #ffffff;
  --color-surface: #f4f6fa;
  --color-text: #172033;
  --color-border: #d7dce5;
}

[data-theme="dark"] {
  color-scheme: dark;
  --color-page: #111827;
  --color-surface: #1f2937;
  --color-text: #f5f7fb;
  --color-border: #4b5563;
}
~~~

The brand token is a build-time Sass value, interpolated into the CSS custom property. Page, surface, text, and border colors are CSS custom properties so the browser can select their values from the active theme.

## 6. Create a reusable button component

Create <code>src/scss/components/_button.scss</code>:

~~~scss
@use "../foundation" as foundation;

.button {
  display: inline-flex;
  align-items: center;
  justify-content: center;
  min-height: 2.75rem;
  padding: foundation.space(2) foundation.space(4);
  border: 1px solid transparent;
  border-radius: 0.5rem;
  font: inherit;
  font-weight: 700;
  text-decoration: none;
  cursor: pointer;

  @include foundation.focus-ring();

  &--primary {
    color: white;
    background: var(--color-brand);
  }

  &--secondary {
    color: var(--color-text);
    background: var(--color-surface);
    border-color: var(--color-border);
  }

  @include foundation.from(wide) {
    min-height: 3rem;
  }
}
~~~

The component uses the public foundation API. Sass resolves the spacing values and emits the breakpoint query during compilation. The browser resolves the theme properties when it applies the CSS.

## 7. Create the CSS entry point

Create <code>src/scss/main.scss</code>:

~~~scss
@use "foundation" with (
  $brand: #6d28d9
);
@use "theme";
@use "components/button";

* {
  box-sizing: border-box;
}

body {
  min-width: 20rem;
  margin: 0;
  padding: 2rem;
  color: var(--color-text);
  background: var(--color-page);
  font-family: system-ui, sans-serif;
  line-height: 1.5;
}

.demo {
  display: grid;
  gap: 1rem;
  max-width: 42rem;
  margin-inline: auto;
  padding: 1.5rem;
  color: var(--color-text);
  background: var(--color-surface);
  border: 1px solid var(--color-border);
  border-radius: 0.75rem;
}
~~~

The entry point configures the foundation before loading the theme and component. Those modules refer to the same configured foundation module. All <code>@use</code> rules appear before the style rules.

## 8. Add a page to view the result

Create <code>index.html</code>:

~~~html
<!doctype html>
<html lang="en" data-theme="light">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>SCSS quick reference demo</title>
    <link rel="stylesheet" href="dist/main.css">
  </head>
  <body>
    <main class="demo">
      <h1>SCSS quick reference</h1>
      <p>
        Sass creates the stylesheet at build time. CSS custom properties
        let the browser apply the selected theme.
      </p>
      <div>
        <a class="button button--primary" href="#primary">Primary action</a>
        <a class="button button--secondary" href="#secondary">Secondary action</a>
      </div>
    </main>
  </body>
</html>
~~~

After compilation, open the page through a local development server. A local server avoids browser restrictions that can affect file URLs and makes it easier to use developer tools.

## 9. What the build should demonstrate

The generated CSS should contain the resolved build-time values and preserve the browser-level theme variables. The output will include rules with these characteristics:

~~~css
:root {
  --color-brand: #6d28d9;
  --color-page: #ffffff;
  --color-surface: #f4f6fa;
}

[data-theme=dark] {
  --color-page: #111827;
}

.button {
  padding: 0.5rem 1rem;
}

.button:focus-visible {
  outline: 3px solid #6d28d9;
  outline-offset: 2px;
}

.button--primary {
  color: white;
  background: var(--color-brand);
}

@media (min-width: 48rem) {
  .button {
    min-height: 3rem;
  }
}
~~~

This is a representative excerpt. The complete generated file will also contain the page, surface, border, and secondary button rules, plus source-map information depending on the compiler options.

Notice the different timing:

- <code>foundation.space(4)</code> is evaluated by Sass and becomes a CSS length.
- <code>foundation.from(wide)</code> becomes a CSS media query.
- <code>var(--color-page)</code> remains for the browser to resolve.
- The configured Sass brand value is inserted into the theme custom property at compile time.

## 10. Practice tasks

### Task A: Change the brand during compilation

In <code>main.scss</code>, change the configured brand to another valid color. Rebuild the CSS. Check that the emitted <code>--color-brand</code> value and focus outline change.

### Task B: Change the theme at runtime

Set <code>data-theme="dark"</code> on the root HTML element. The page, surface, text, and border values should change without compiling Sass again. The brand remains the compile-time configured value.

### Task C: Add a token

Add a new spacing step to the private map. Use it through <code>space()</code> in the component. Confirm that component source depends on the public function rather than the internal map.

### Task D: Add another breakpoint

Add a named breakpoint to the private map and use the <code>from()</code> mixin to change the demo layout. Try an unknown name and read the Sass error message.

### Task E: Add a themeable component value

Add a button-specific CSS custom property with a fallback, such as <code>var(--button-radius, 0.5rem)</code>. Override it on a particular button class and verify that only the intended component changes.

### Task F: Inspect the CSS and source map

Compile the stylesheet and inspect <code>dist/main.css</code>. Use browser developer tools to inspect the button and, if source maps are enabled, navigate from the generated rule back to its SCSS source.

## 11. Review checklist

Before treating this mini project as complete, confirm:

- Sass source is under <code>src/scss</code> and generated CSS goes to <code>dist</code>.
- Only the entry point is compiled as the application's stylesheet.
- The entry point loads modules with <code>@use</code>.
- The public module entry point forwards a small, intentional API.
- Private token maps are accessed through checked public functions or mixins.
- Sass values are used for build-time choices.
- CSS custom properties are used for runtime theme values.
- The component has a visible keyboard focus indicator.
- Both build and watch commands are recorded in the project scripts.
- Generated CSS is reproducible from source and is not edited manually.
