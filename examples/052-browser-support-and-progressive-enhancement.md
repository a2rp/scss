# Browser support and progressive enhancement - Examples

This exercise creates a small SCSS page with a working baseline and optional CSS enhancements. It demonstrates declaration fallbacks, <code>@supports</code> feature queries, selector queries, Sass modules, and a lightweight browser test matrix.

## 1. Create the project

~~~text
progressive-enhancement-demo/
  index.html
  src/
    _base.scss
    _breakpoints.scss
    _features.scss
    app.scss
  dist/
    app.css                  generated by Dart Sass
~~~

The baseline uses ordinary document flow, a solid color, and a flex column. Supported browsers can apply a grid layout, a gradient, a newer focus selector, and bounded fluid width. Each enhancement has a useful fallback.

## 2. Define a small Sass breakpoint module

Create <code>src/_breakpoints.scss</code>:

~~~scss
@use "sass:map";

$breakpoints: (
  content-wide: 48rem
);

@mixin above($name) {
  $min-width: map.get($breakpoints, $name);

  @if $min-width == null {
    @error "Unknown breakpoint: #{$name}";
  }

  @media (min-width: $min-width) {
    @content;
  }
}
~~~

This breakpoint describes when the sample's content can use two columns. It does not try to identify a specific device.

## 3. Write the baseline styles

Create <code>src/_base.scss</code>:

~~~scss
:root {
  color-scheme: light;
  font-family: system-ui, sans-serif;
  line-height: 1.5;
  color: #1e293b;
  background: #f8fafc;
}

* {
  box-sizing: border-box;
}

body {
  margin: 0;
}

.site-shell {
  width: calc(100% - 2rem);
  max-width: 72rem;
  margin-inline: auto;
}

.site-header {
  padding-block: 1.5rem;
}

.site-title {
  margin: 0;
  font-size: 2rem;
}

.site-intro {
  max-width: 65ch;
  color: #475569;
}

.site-link {
  color: #312e81;
  text-underline-offset: 0.2em;
}

.site-link:focus {
  outline: 3px solid #7c3aed;
  outline-offset: 3px;
}

// Keep the fallback focus indicator. In browsers that understand
// :focus-visible, avoid showing it for pointer focus that is not keyboard focus.
@supports selector(:focus-visible) {
  .site-link:focus:not(:focus-visible) {
    outline: none;
  }

  .site-link:focus-visible {
    outline: 3px solid #7c3aed;
    outline-offset: 3px;
  }
}

.page-footer {
  margin-block: 3rem 1rem;
  padding-block: 1rem;
  border-block-start: 1px solid #cbd5e1;
  color: #475569;
}
~~~

The <code>:focus</code> rule is the baseline. A browser that supports <code>:focus-visible</code> can refine when the indicator appears, while keyboard focus still receives a visible outline.

## 4. Add fallback and enhanced feature styles

Create <code>src/_features.scss</code>:

~~~scss
@use "breakpoints" as bp;

.feature-list {
  display: flex;
  flex-direction: column;
}

// Fallback spacing does not depend on Flexbox gap support.
.feature-list > * + * {
  margin-block-start: 1rem;
}

.feature-card {
  min-inline-size: 0;
  padding: 1rem;
  border: 1px solid #cbd5e1;
  border-radius: 0.75rem;
  background-color: #fff;
  background-image: linear-gradient(135deg, #fff, #f5f3ff);
}

.feature-card h3 {
  margin-block: 0 0.5rem;
}

.feature-card p {
  margin-block: 0;
  color: #475569;
}

.feature-card a {
  display: inline-block;
  margin-block-start: 1rem;
}

// Grid and gap are one enhancement; the flex column remains the baseline.
@supports (display: grid) and (gap: 1rem) {
  .feature-list {
    display: grid;
    grid-template-columns: minmax(0, 1fr);
    gap: 1rem;
  }

  .feature-list > * + * {
    margin-block-start: 0;
  }

  @include bp.above(content-wide) {
    .feature-list {
      grid-template-columns: repeat(2, minmax(0, 1fr));
    }
  }
}

// Keep the solid color and max-width baseline; enhance with newer values
// only when the browser recognizes the complete declaration.
@supports (width: min(100% - 2rem, 72rem)) {
  .site-shell {
    width: min(100% - 2rem, 72rem);
  }
}

@supports (color: color-mix(in srgb, #312e81, white)) {
  .feature-card a {
    color: color-mix(in srgb, #312e81, white 10%);
  }
}
~~~

The normal stylesheet provides a flex layout, neighbor margins, solid background, and maximum width. The feature queries add Grid, gap, a bounded width expression, and a newer color function when the browser accepts their conditions.

These queries test declarations, not every implementation detail. If the product supports older browsers or a feature combination with known partial implementations, check the exact compatibility data and test the resulting behavior. This example's target browsers should be selected by the project using it.

## 5. Load the modules from one entry point

Create <code>src/app.scss</code>:

~~~scss
@use "base";
@use "features";
~~~

Sass loads each module through <code>@use</code> and combines its CSS into the entry point. The browser receives the compiled CSS, including the fallback rules and conditional enhancements.

## 6. Add meaningful HTML

Create <code>index.html</code>:

~~~html
<!doctype html>
<html lang="en">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <meta name="description" content="A Sass progressive enhancement example">
    <title>Progressive enhancement with Sass</title>
    <link rel="stylesheet" href="dist/app.css">
  </head>
  <body>
    <header class="site-header site-shell">
      <h1 class="site-title">Progressive enhancement</h1>
    </header>

    <main class="site-shell">
      <p class="site-intro">
        This page starts with a readable baseline and adds CSS features when
        the browser supports them.
      </p>

      <section aria-labelledby="features-heading">
        <h2 id="features-heading">Layout features</h2>

        <div class="feature-list">
          <article class="feature-card" id="feature-grid">
            <h3>Grid layout</h3>
            <p>
              The cards remain in a vertical flex layout unless the browser
              supports the Grid enhancement.
            </p>
            <a class="site-link" href="#details-grid">Read about the layout</a>
          </article>

          <article class="feature-card" id="feature-color">
            <h3>Color fallback</h3>
            <p>
              A solid background color remains when the browser cannot use
              the decorative gradient.
            </p>
            <a class="site-link" href="#details-color">Read about the color</a>
          </article>
        </div>
      </section>

      <section aria-labelledby="details-heading">
        <h2 id="details-heading">Implementation details</h2>
        <article id="details-grid">
          <h3>Layout fallback</h3>
          <p>
            A flex column keeps both cards in document order. Grid and its
            two-column layout are conditional enhancements.
          </p>
          <a class="site-link" href="#feature-grid">Back to Grid layout</a>
        </article>
        <article id="details-color">
          <h3>Color fallback</h3>
          <p>
            A solid background remains readable if a browser does not
            understand the gradient declaration.
          </p>
          <a class="site-link" href="#feature-color">Back to Color fallback</a>
        </article>
      </section>
    </main>

    <footer class="page-footer site-shell">
      <p>Core content remains available in the baseline layout.</p>
    </footer>
  </body>
</html>
~~~

The links point to real sections in the example. The content is present in the HTML rather than being inserted by a script, so the layout enhancement is not required to access it.

## 7. Compile the stylesheet

From the project directory, create the output folder and compile:

~~~powershell
New-Item -ItemType Directory -Force dist
sass --style=expanded src/app.scss dist/app.css
~~~

Open <code>index.html</code> through a local static server. If the <code>sass</code> command is not installed, install Dart Sass using the official Sass instructions first.

## 8. Review the fallback and enhanced paths

Inspect the page in the browsers and environments declared by your own support policy:

1. Check that the cards remain readable and in order in the baseline flex layout.
2. Check that the cards form two columns when the viewport is wide enough and Grid is supported.
3. Disable or emulate unsupported features where practical, then confirm that the fallback declarations remain effective.
4. Verify the solid color remains if the gradient is removed or unsupported.
5. Tab through the links. Focus should remain visible in both the baseline and enhanced selector paths.
6. Check the compiled <code>dist/app.css</code> to see which rules Sass emitted. The feature queries should still be present for the browser to evaluate.
7. Check narrow widths, zoom, and text enlargement for clipping or horizontal overflow.

A browser that accepts <code>display: grid</code> may still have a limitation in a related behavior. Use compatibility information and tests for the exact layout features your target requires; do not treat one positive feature query as proof that the complete design works.

## 9. Extend the exercise

- Add an icon with an image fallback and confirm the image has an appropriate text alternative when meaningful.
- Add a second feature query for a selector, then keep the base selector outside the query.
- Choose a feature with limited availability and document its baseline behavior and enhanced behavior.
- Add an actual browser/version matrix based on the audience for your own project.
- If your build uses a CSS compatibility tool, add it as a separate build step, configure the target browsers, and compare its output with the compiled Sass.

## Expected behavior

- The HTML content is available regardless of the CSS enhancement path.
- A flex column and solid color provide a useful baseline.
- Grid, grid spacing, bounded width, gradient, and color mixing are applied only when their CSS conditions are accepted.
- Keyboard focus remains visible, with a more specific focus-visible treatment where supported.
- The compiled CSS contains the Sass output and the browser-evaluated feature queries.
