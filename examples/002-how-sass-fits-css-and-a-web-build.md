# 002. How Sass Fits CSS and a Web Build — Examples

This example follows an SCSS file through two workflows:

1. Compile SCSS directly with the Sass CLI.
2. Import SCSS into a Vite application.

The first workflow makes the compiler boundary easy to see. The second shows how a build tool can connect Sass to a larger application.

## Example 1: Compile SCSS with the Sass CLI

### Project files

Create this small project:

~~~text
sass-cli-demo/
├── index.html
├── package.json
├── src/
│   └── styles.scss
└── styles.css       generated by Sass
~~~

Initialize the project and install Sass:

~~~sh
mkdir sass-cli-demo
cd sass-cli-demo
npm init -y
npm install -D sass
mkdir src
~~~

Create src/styles.scss:

~~~scss
$brand-color: #1769aa;
$surface-color: #f4f7fb;
$text-color: #17212b;

.card {
  max-width: 32rem;
  padding: 1.5rem;
  color: $text-color;
  background: $surface-color;
  border: 2px solid $brand-color;
  border-radius: 0.75rem;

  h1 {
    margin-top: 0;
    color: $brand-color;
  }

  p {
    line-height: 1.6;
  }

  &:hover {
    border-color: #0d4f85;
  }
}
~~~

Create index.html:

~~~html
<!doctype html>
<html lang="en">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>Sass CLI example</title>
    <link rel="stylesheet" href="./styles.css">
  </head>
  <body>
    <main class="card">
      <h1>SCSS becomes CSS</h1>
      <p>
        Sass compiles this source file. The browser loads the generated CSS.
      </p>
    </main>
  </body>
</html>
~~~

Compile the source file:

~~~sh
npx sass src/styles.scss styles.css
~~~

The command reads src/styles.scss and writes styles.css. The generated CSS contains ordinary selectors and resolved values:

~~~css
.card {
  max-width: 32rem;
  padding: 1.5rem;
  color: #17212b;
  background: #f4f7fb;
  border: 2px solid #1769aa;
  border-radius: 0.75rem;
}
.card h1 {
  margin-top: 0;
  color: #1769aa;
}
.card p {
  line-height: 1.6;
}
.card:hover {
  border-color: #0d4f85;
}
~~~

The browser loads styles.css because that is the file referenced by the HTML. It does not load src/styles.scss.

### Watch for changes

To recompile whenever the source changes, run:

~~~sh
npx sass --watch src/styles.scss:styles.css
~~~

Leave the watcher running while editing. After Sass reports a successful compilation, refresh the page to see the updated CSS.

If you want to serve the page locally instead of opening the HTML file directly, use any static development server available in your environment. The server serves the HTML and generated CSS; the Sass watcher compiles the source.

## Example 2: Import SCSS into Vite

Vite can process an SCSS import as part of the application. This example assumes Node.js and npm are installed.

Create a vanilla Vite project and add Sass:

~~~sh
npm create vite@latest sass-vite-demo -- --template vanilla
cd sass-vite-demo
npm install
npm install -D sass
~~~

Use the Vite project’s existing source directory. Create src/styles.scss:

~~~scss
$brand-color: #1769aa;

.page {
  min-height: 100vh;
  padding: 2rem;
  font-family: system-ui, sans-serif;
  color: #17212b;
  background: #f4f7fb;

  .button {
    padding: 0.65rem 1rem;
    color: white;
    background: $brand-color;
    border: 0;
    border-radius: 0.5rem;
    cursor: pointer;

    &:hover {
      background: #0d4f85;
    }
  }
}
~~~

In src/main.js, import the SCSS file:

~~~js
import "./styles.scss";
import "./style.css";

const app = document.querySelector("#app");
const main = document.createElement("main");
main.className = "page";
main.innerHTML = "<h1>SCSS inside a Vite app</h1><p>Vite processes the imported stylesheet as part of the application.</p><button class=\"button\" type=\"button\">Try the button</button>";
app.replaceChildren(main);
~~~

If the generated Vite starter still imports its own CSS file, keep that import or remove it according to the project’s structure. Avoid importing the same styling twice unintentionally.

Start the development server:

~~~sh
npm run dev
~~~

Open the local address printed by Vite. Edit src/styles.scss and observe the development workflow update the page. The Vite development server processes the imported stylesheet; there is no separate Sass output path to add to the HTML in this setup.

Build the application for production:

~~~sh
npm run build
~~~

Vite writes production output to its configured build directory, commonly dist. Use the project’s configured deployment workflow to publish that output.

The Vite starter template can change over time, so follow the files and scripts generated by the installed Vite version. The important Sass integration steps are installing Sass and importing the SCSS file from the application.

## Compare the workflows

| Detail | Sass CLI | Vite |
| --- | --- | --- |
| How SCSS is connected | The CLI command names the source and output paths. | The application imports the SCSS file. |
| Who runs Sass | The Sass CLI process. | The project build tool invokes the Sass integration. |
| How the page receives styles | HTML links to the generated CSS file. | The tool includes the imported style in its application workflow. |
| Useful for | Seeing and controlling direct Sass compilation. | Managing styles alongside a JavaScript application and its assets. |

## Troubleshooting

### The HTML page has no styling

Confirm that the CLI generated styles.css and that the link in index.html points to that exact path.

### The CSS file is stale

Check that the watcher is still running and that it watches src/styles.scss. Read the terminal for Sass errors.

### Vite reports that it cannot process SCSS

Confirm that Sass was installed in the Vite project and that the imported filename ends with .scss. Review the current Vite CSS feature documentation for version-specific setup.

### A rule appears in CSS but not on the page

Inspect the element in browser developer tools. Check whether the selector matches, whether the declaration is crossed out, and which rule controls the computed value.

## Try these changes

1. Change the brand color in the SCSS source and confirm that the generated CSS changes.
2. Add a nested .icon rule inside .button and inspect the selector Sass emits.
3. Temporarily break a Sass declaration, then read the compiler error and confirm whether output was updated.
4. In the CLI project, change the stylesheet link to a wrong path and inspect the browser’s network panel.
5. In the Vite project, remove the SCSS import, reload the page, and note the difference.
6. Compare the readable source files with the generated CSS or Vite production output.
