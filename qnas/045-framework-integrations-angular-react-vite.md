# Framework integrations: Angular, React, and Vite — Q&A

This Q&A covers Sass integration in Angular CLI projects and React applications using a bundler such as Vite. Framework and build-tool options can change between releases; check the documentation for the versions recorded in the project lockfile.

## 1. Can a browser load an SCSS file directly?

No. Browsers consume CSS, not Sass syntax. A compiler in the development or production pipeline must transform SCSS into CSS before it is delivered to the browser.

## 2. Which part of an application usually compiles Sass?

The framework CLI or bundler usually owns compilation. Angular CLI compiles application styles as part of its workflow. In a Vite project, Vite processes imported Sass files when a Sass implementation is installed.

## 3. Does React compile Sass?

No. React does not define a Sass compiler or CSS bundling convention. The project's framework, bundler, or loader must support SCSS imports.

## 4. How do I create an Angular project configured for SCSS?

Use the Angular CLI style option when creating the project:

~~~sh
ng new storefront --style=scss
~~~

The CLI generates SCSS styles and configures its build to process them. The exact generated file layout can vary with CLI version and project options.

## 5. Can an existing Angular project switch from CSS to SCSS?

Yes, but make the change consistently. Rename or convert the intended stylesheet files, update component metadata and workspace configuration references, and confirm each relevant builder processes SCSS. Do not change only the extension while leaving references pointed at the old path.

## 6. Where should Angular global styles go?

A common global entry is <code>src/styles.scss</code>. The Angular workspace configuration includes global files through the build target's <code>styles</code> option. Global resets, document defaults, and site-wide styles belong in this graph.

## 7. Where should Angular component styles go?

Place component-specific rules in the component stylesheet referenced by that component's metadata. Follow the style URL or style URLs convention generated by the Angular version in the project.

## 8. Does Sass scope Angular component styles?

No. Sass transforms Sass syntax to CSS. Angular's component style and view-encapsulation system determines how component styles are applied or scoped.

## 9. How do I add a Sass include path in Angular?

Configure <code>stylePreprocessorOptions.includePaths</code> for the relevant workspace build target. For example:

~~~json
{
  "projects": {
    "storefront": {
      "architect": {
        "build": {
          "options": {
            "stylePreprocessorOptions": {
              "includePaths": ["src/styles"]
            }
          }
        }
      }
    }
  }
}
~~~

Check the actual project name and builder in <code>angular.json</code>. The setting belongs to the target configuration, and additional targets may need corresponding options.

## 10. Does an Angular Sass include path load a file globally?

No. It adds search locations for Sass imports or modules. It does not insert that file into the browser stylesheet. Load the stylesheet through a global entry point or a component style that uses it.

## 11. How should Angular styles share tokens?

Put Sass variables, functions, and mixins in a partial or module, then load them with <code>@use</code>. Use a relative module URL or a configured include path. Keep selectors in global stylesheets that should be emitted once.

## 12. What is the difference between a component style and a global style in Angular?

A global style is included for the application as a whole through workspace configuration. A component style is attached to a particular component through its metadata and is subject to Angular's style-encapsulation behavior.

## 13. What must be installed for Vite to process SCSS?

Install the Sass preprocessor in the project, such as <code>sass-embedded</code> or <code>sass</code>, according to platform support and project requirements. Vite has preprocessor integration; a separate Vite Sass plugin is usually unnecessary.

## 14. How do I import SCSS into a Vite application?

Import it from a JavaScript or TypeScript module:

~~~js
import './styles/main.scss';
~~~

The imported stylesheet becomes part of Vite's style pipeline and production build.

## 15. How do I apply Sass styles to a React component using Vite?

Import the component stylesheet in its module and use the class in JSX:

~~~jsx
import './ProductCard.scss';

export function ProductCard({ name }) {
  return <article className="product-card">{name}</article>;
}
~~~

The Sass compiler produces CSS. A normal class selector is still global unless another feature, such as CSS Modules, scopes the generated class name.

## 16. Does a Vite React project need a Sass plugin?

Usually no. Vite supports Sass files when the Sass package itself is installed. Add a plugin only if a specific project requirement is not met by built-in preprocessor support.

## 17. How do I set Sass preprocessor options in Vite?

Use <code>css.preprocessorOptions.scss</code> in Vite configuration. The values passed there are Sass compiler options supported by the installed versions. Check the current Vite and Sass docs before adding a particular option.

## 18. What does Vite's additionalData option do?

It prepends Sass source to each processed style file. It can make Sass-only tools such as variables or mixins available without repeating an import. If the injected source emits CSS, that CSS can be repeated in every compiled stylesheet.

## 19. Should every stylesheet inject a shared Sass module automatically?

Not necessarily. Explicit <code>@use</code> statements make dependencies visible in each file. Use automatic injection only when it simplifies the project and the injected module does not generate unwanted CSS.

## 20. Is Sass @use the same as CSS Modules?

No. Sass <code>@use</code> organizes compile-time Sass members such as variables, functions, and mixins. CSS Modules transform class names and provide a mapping for application code to use. They work at different stages and can be combined.

## 21. Does a file named Button.module.scss automatically work in every React app?

No. That naming convention is supported by build tools such as Vite when the relevant preprocessing is configured. React itself does not define the convention. Check the bundler or framework documentation.

## 22. Does CSS Modules replace Sass modules?

No. CSS Modules handle local class names in the compiled CSS. Sass modules expose and namespace Sass members. A stylesheet may use both, for example Sass <code>@use</code> for tokens and a CSS Modules build convention for local classes.

## 23. How can shared Sass files avoid generating repeated CSS?

Keep token, function, and mixin modules free of top-level selectors where practical. Load global base styles once from the global entry point. A module containing CSS-producing rules can emit that CSS when included in multiple entry files.

## 24. Can I use @import to load Sass modules?

Legacy Sass <code>@import</code> is deprecated for Sass module loading. Use <code>@use</code> for Sass modules and use framework or JavaScript imports to connect stylesheets to the application. Some bundlers also process CSS imports, but that is a separate mechanism.

## 25. Can a file be resolvable through @use but still absent from the page?

Yes. Sass resolving a module means its source can be loaded during compilation. It does not necessarily make that stylesheet a global browser entry. The application must import or configure an entry that includes the emitted CSS.

## 26. How should asset URLs in SCSS be handled?

Use URLs valid for the source file and the selected build tool, then inspect the production output. Bundlers can rewrite and emit assets; standalone Sass compilation may require a separate asset-copy step. Do not assume every tool resolves URLs identically.

## 27. Why does SCSS work in the dev server but not in production?

The production target may use a different configuration, omit a style entry, fail to include the Sass dependency, or resolve asset paths differently. Run the project's production build and inspect the emitted CSS and asset references.

## 28. Why does the Angular build work but a test target miss styles?

Test and build targets can have different style inputs or preprocessor settings. If tests need global styles or a particular include path, configure the relevant test builder too.

## 29. Why does a test runner fail when it imports an SCSS file?

Some test environments do not process style imports like the browser bundler. Use the test runner's documented style handling or mock/configure style imports as appropriate. Keep the production Sass pipeline separate from any test-specific transform.

## 30. Can I run Sass CLI and Vite on the same entry file?

Avoid compiling the same entry independently in both pipelines unless the duplication is intentional. Pick a single owner for each entry to prevent duplicate or conflicting CSS assets.

## 31. Where should the Sass dependency be recorded?

Declare it in the project manifest, usually as a development dependency, and commit the lockfile. That lets local installations and CI use the project-selected compiler rather than an unrelated global executable.

## 32. Should Sass be installed globally for framework integration?

A global install is not a substitute for the project dependency. A global executable may hide a missing package locally, while CI or another developer will not have that same global environment.

## 33. How do I choose between sass-embedded and sass?

Follow the current Vite or Sass installation guidance and the target platform requirements. Vite currently recommends <code>sass-embedded</code> for performance where supported and documents <code>sass</code> as an alternative. Ensure the selected package is lockfile-managed.

## 34. Does Angular's styles option replace component stylesheet metadata?

No. The workspace's global <code>styles</code> option includes application-wide files. Component metadata points to component-specific style files. They serve distinct roles.

## 35. How should I decide between global SCSS and component SCSS?

Put document-wide rules, resets, and global typography in the global entry. Put a component's own selectors beside that component. Share Sass-only tools through modules and share actual global CSS through a stylesheet loaded once.

## 36. Why might imported Sass URLs be rewritten by Vite?

Vite performs CSS processing and asset URL rebasing for supported preprocessor imports. The exact behavior and limitations are documented by Vite and can vary by syntax and version. Inspect the built result if a URL includes interpolation or unusual resolution.

## 37. Does every Vite version use the same Sass implementation?

Not necessarily. Vite's documented package-selection behavior can depend on its version and which Sass packages are installed. Keep dependencies locked and consult the matching version's documentation if implementation choice matters.

## 38. What should I check when a shared @use module cannot be found?

Check the relative path from the importing file, filename and partial naming, configured include/load paths, and whether the correct build target has that configuration. Try a relative module URL to isolate a search-path issue.

## 39. What is the safest way to verify an integration?

Run the project's documented development command and production build, then confirm the styles appear in the built output. Also check any test target that consumes styles. Keep the compiler declared in the project and the same configuration available in CI.

## 40. What is the integration checklist?

- Sass implementation is installed in the project and locked.
- Global and component styles are connected through the correct mechanisms.
- Sass modules resolve using documented paths.
- Global CSS-producing modules are loaded intentionally.
- CSS Modules or framework scoping are not confused with Sass modules.
- Development, tests, and production use compatible styles and options.
- Asset URLs are valid after bundling.
- One pipeline owns each Sass entry point.
